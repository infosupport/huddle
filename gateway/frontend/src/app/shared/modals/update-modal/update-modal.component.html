What's the difference?
Three things worth knowing before you pick.
Why split it up?

The node needs host access for Docker and the database; the proxies don't. Separating them keeps the privileged part small and the network part replaceable.

Devcontainer or sbx?

Both are safe. Devcontainers are the faster of the two; sbx is the more capable one, because a full VM handles more than a container can.

One trade-off

sbx uses Huddle's proxy instead of native sbx firewalling. That keeps one set of firewall rules, but it makes sbx depend on Huddle.

Keep Huddle running

Because everything routes through the gateway, an sbx won't start while Huddle is stopped. If a sandbox refuses to boot, check Huddle first. It's almost always this.
