# Host pipe

The gateway runs in a container and cannot see or run anything on the host. A few features need the
host anyway: browsing host folders (to pick mounts) and driving host-side environment tools such as
Docker Sandboxes (`sbx`). The **host pipe** is the one channel for that.

It is a folder, not a socket. Real FIFOs, Unix sockets and Windows named pipes do not cross a Docker
bind mount on every platform (a Linux container on Windows cannot reach a named pipe, and `bind()` on
a Windows drive mounted into WSL fails), but plain files do. Python-free, stdlib-only Node on the host.

```
host                                   gateway container
~/.huddle/pipe/   <── bind mount ──>   /huddle-home/pipe/       (existing ~/.huddle mount, no new one)
```

Devcontainers and sandboxes never get this folder mounted. Only the gateway (which already holds the
Docker socket, i.e. is already fully trusted by the host) and the host agent can write to it.

## Lifecycle

- `huddle init` (and `huddle restart`) starts the host agent in the background, replacing a running one
  so it always runs the current CLI version: `huddle pipe serve`, detached, `windowsHide`, logging to
  `~/.huddle/pipe/host.log`.
- `huddle pipe status` / `huddle pipe stop` / `huddle pipe serve` (foreground, for debugging).
- The agent writes a heartbeat `~/.huddle/pipe/host.json` every 2 s:
  `{ "v": 1, "pid": 123, "version": "<cli version>", "platform": "win32|darwin|linux", "tools": ["sbx"], "startedAt": "<iso>", "updatedAt": "<iso>" }`
  The gateway treats the agent as **offline** when the file is missing or `updatedAt` is older than 10 s.
- On start the agent deletes leftover `*.in`, `*.busy`, `*.out`, `*.tmp` older than 1 hour.

## Protocol (v1)

All files are UTF-8 JSON, written to `<name>.tmp` and then renamed (atomic), so a reader never sees a
half-written file. `<id>` is a random 32-hex string generated by the caller.

1. Gateway writes `<id>.in`:  `{ "v": 1, "op": "<op>", "args": { ... } }`
2. Agent polls every 100 ms, claims a request by renaming `<id>.in` → `<id>.busy` (so it is handled once
   and slow requests run concurrently), runs it, writes `<id>.out`, deletes `<id>.busy`.
3. Gateway polls for `<id>.out`, reads and deletes it.
   Reply: `{ "ok": true, "result": ... }` or `{ "ok": false, "error": { "code": "<code>", "message": "..." } }`
4. Timeouts (gateway side): if `<id>.in` is still unclaimed after 5 s the gateway deletes it and fails with
   `host_pipe_offline`. Once claimed, it waits up to the per-op timeout (default 30 s, `tool.run` up to the
   `timeoutMs` it passes, max 15 min) and then fails with `host_pipe_timeout`.

Error codes: `bad_request`, `unknown_op`, `not_found`, `not_allowed`, `tool_missing`, `internal`
(agent side); `host_pipe_offline`, `host_pipe_timeout` (gateway side).

### Operations

| op | args | result |
|---|---|---|
| `host.info` | `{}` | `{ platform, version, home, tools: { [name]: { available, path?, version? } } }` |
| `fs.list` | `{ path?: string }` | `HostFolderListing` (below). No `path` → the roots. |
| `tool.run` | `{ tool: string, args: string[], timeoutMs?: number }` | `{ code: number, stdout: string, stderr: string }` |

**`fs.list`**: lists the immediate subfolders of one folder (port of `host-browse.ts` from
`feat/sbx-sandboxes-rebased`). No path → roots: every readable drive `X:/` on Windows, `/` elsewhere, plus
the home folder. Paths are host paths in Huddle notation (forward slashes, upper-case drive letter, no
trailing slash except roots: `C:/Users/me`, `/home/me`). Hidden folders and symlinked folders are included;
at most 2000 entries, then `truncated: true`. A folder that cannot be read → `ok:false`, `not_found`.
Sorted case-insensitively.

```ts
interface HostFolder { path: string; name: string }          // name: leaf, or 'C:' / '/' for roots
interface HostFolderListing { path: string; folders: HostFolder[]; truncated: boolean; max: number }  // path '' for roots
```

This is **not** an authorization boundary. Mount paths are still validated by `hostPathError` and the
operator token, exactly as before; listing only replaces the old `huddle indexfolder` snapshot.

**`tool.run`**: runs an allowlisted host binary with an argv array, never a shell. The allowlist lives in
the host agent (`TOOLS` in `cli/src/pipe/tools.ts`), today only `sbx` (override the binary with
`HUDDLE_SBX_BIN`). The binary is resolved on `PATH` (`sbx`, `sbx.exe`); `.bat`/`.cmd` are refused (cmd.exe
would let argv inject commands). stdin is closed, `windowsHide: true`, output capped at 16 MB per stream.
Interactive commands (TTY) are not supported.

## Gateway side

- `gateway/src/host-pipe.ts`: `hostPipe.call(op, args, { timeoutMs })`, `hostPipe.status()`
  (reads the heartbeat). Pipe dir = `${HUDDLE_HOME_DIR}/pipe` (override `HUDDLE_PIPE_DIR`).
- `gateway/src/environments/`: provider registry, so sbx is one implementation, not a special case.

```ts
interface EnvironmentProvider {
  id: string;                 // 'sbx'
  label: string;              // 'Docker Sandbox'
  status(): Promise<ProviderStatus>;                         // { id, label, available, version?, error?, agents: string[] }
  list(): Promise<SandboxInfo[]>;                            // { name, provider, status?, workspaces?: string[] }
  create(spec: SandboxSpec): Promise<SandboxCreateResult>;   // spec: { name, agent, workspaces: {path, readOnly}[] }
  remove(name: string, opts: { force: boolean }): Promise<void>;
}
```

Adding an environment = one provider file in `gateway/src/environments/` + its binary in the host
agent's `TOOLS`. Nothing in the API, the pipe or the frontend is sbx-specific.

Huddle only removes sandboxes it created: a provider-agnostic table `sandboxes(provider, name, created_at)`.

### HTTP API (operator token, like every other `/api` route)

| method + path | body / query | response |
|---|---|---|
| `GET /api/host-pipe` | | `{ online, version?, platform?, tools?: string[], updatedAt? }` |
| `GET /api/host-folders` | `?path=` | `HostFolderListing`; 503 `{ error: 'host_pipe_offline' }`, 404 `not_found`, 400 invalid path |
| `GET /api/environments` | | `{ providers: ProviderStatus[] }` |
| `GET /api/environments/:provider/sandboxes` | | `{ sandboxes: SandboxInfo[] }` |
| `POST /api/environments/:provider/sandboxes` | `{ name?, agent, workspaces: {path, readOnly}[] }` | `SandboxCreateResult` `{ name, ok, steps: {label, command, code, stdout, stderr}[] }` |
| `DELETE /api/environments/:provider/sandboxes/:name` | `?force=1` | `{ ok: true }`; 404 if Huddle did not create it |

Removed: `GET/POST/DELETE /api/indexed-folders`, the `indexed_folders` table (dropped on startup), and the
`huddle indexfolder` CLI command.

### sbx (first provider)

argv only, via `tool.run` with tool `sbx`:

- status: `sbx version`
- list: `sbx ls --json` (fall back to parsing the `sbx ls` table)
- create: `sbx create --name <name> <agent> <path> [<path>[:ro] ...]` (first workspace is never read-only),
  timeout 15 min
- remove: `sbx rm [--force] <name>`

Sandbox names: `^[a-z0-9][a-z0-9-]{0,62}$`; default `huddle-<leaf of first workspace>-<4 hex>`.
Agents offered: `claude`, `codex`, `copilot`, `gemini`, `shell` (provider-defined list).

Out of scope for now (were the complicated part of `feat/sbx-sandboxes-rebased`): routing sandbox egress
through the Huddle proxy, per-sandbox identity, policy reconcile, SSH/IDE connect.
